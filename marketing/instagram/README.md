# LiraTek Instagram

Posts for the LiraTek Instagram account, built as code: each post is a `post.json`, rendered locally to PNG slides or an MP4 reel, approved in a small review app, then (later) published through the official Instagram Graph API. Standalone folder — not a Yarn workspace.

## Quick start

Needs `ffmpeg` on PATH (reels) and Playwright, which is resolved from the repo root `node_modules` (run `yarn install` at the root once).

```bash
node render.mjs              # render every post into posts/<id>/media/
node render.mjs 04           # render one post (id prefix match)
node review/server.mjs       # review app → http://localhost:4747
node publish.mjs             # dry run: prints what would be published, sends nothing
```

## Folder layout

```
assets/brand/     logos, demo.mp4 / demo-ar.mp4, music.wav
assets/shots/     1920×1080 screenshots from the DEMO shop only
lib/templates.mjs feed slide templates (1080×1350)
lib/reels.mjs     reel layouts (1080×1920)
posts/<id>/       post.json + media/ (generated by render.mjs)
review/           local approval app (server.mjs + index.html)
render.mjs        renders slides and reels
publish.mjs       Graph API publisher (dry run by default)
build/            scratch output, git-ignored
```

## Adding a post

1. Copy a post folder of the same kind (`01-intro` image, `04-dollars-lira` carousel, `03-demo-reel` / `07-one-counter-reel` reel) to a new `posts/NN-name/`.
2. Edit `post.json`: `id` (= folder name), `type` (`image` | `carousel` | `reel`), `status: "draft"`, `planned_date` (YYYY-MM-DD), `caption_en`, `caption_ar`, `hashtags`, `sources`, `notes`. Leave `media: []`, `public_urls: []`, `published_id: null`.
3. `node render.mjs NN` and look at it in the review app.

Text fields support `*word*` to colour a word in the accent colour. `sub_ar` adds an Arabic line under most layouts.

**Slide templates** (`slides: [...]`, one entry per image; `image` has one, `carousel` 2+):

| template  | fields                                                                                                           |
| --------- | ---------------------------------------------------------------------------------------------------------------- |
| `hero`    | `eyebrow`, `title`, `title_size` (`md`/`sm`), `body`, `chips[]`, `sub_ar`                                         |
| `shot`    | `eyebrow`, `title`, `title_size`, `body`, `shot: { file, crop: [x,y,w,h], ring?: [x,y,w,h], style? }`, `sub_ar` |
| `list`    | `eyebrow`, `title`, `title_size`, `items: [{ t, d }]`                                                            |
| `numbers` | `eyebrow`, `lines: [{ text, size?, color?, label? }]`, `title`, `sub_ar`                                         |
| `cta`     | `title`, `title_size`, `body`, `button` (default "Talk to us on WhatsApp"), `sub_ar`                             |
| `phone`   | `eyebrow`, `title`, `body`, `sub_ar`, `note`, `rows: [{ k, v }]`                                                 |

`shot.crop` / `ring` are in pixels of the 1920×1080 screenshot in `assets/shots/`.

**Reels** (`type: "reel"`, `reel: {...}`):

- `kind: "framed-video"` — `video` (file in `assets/brand/`), `eyebrow`, `title`, `sub_ar`, `body`, `button`. The landscape video sits in a branded vertical frame; cover is taken at 3s.
- `kind: "scenes"` — `duration` (s), `cover_at` (s), `scenes: [...]`, each with `t0`, `t1` and a `kind`:
  - `text`: `eyebrow`, `title`, `size`, `sub_ar`
  - `shot`: `eyebrow`, `title`, `sub_ar`, `shot` (as above), `top`, `caption`, `caption_top`
  - `logo`: `title`, `sub_ar`, `button`

## Content rules

- **No invented facts.** No prices, customer counts, testimonials, ratings or claims that are not on the landing page. Every claim must trace to `landing/index.html` or `landing/ar.html` (repo root), and that source goes in the post's `sources`.
- **Screenshots only from the demo shop**, never from the live database or a real customer's shop.
- **The phone app is owner-only and for web-app shops only** — say so whenever it is mentioned.

## Review workflow

In the review app each post has a status: `draft` → `approved`, or `changes` (needs edits) / `rejected`. You can also edit captions, hashtags, `planned_date` and notes there. Only `approved` posts are ever published.

## Going live (owner does these steps)

The Meta side changes often — **verify each step in Meta's docs** (developers.facebook.com, Instagram Platform / Content Publishing).

1. Create the Instagram account.
2. Switch it to a Professional account (Business or Creator).
3. Link it to a Facebook Page (verify in Meta docs whether this is still required for your login type).
4. Create a Meta developer app and add the Instagram product.
5. Get a long-lived access token with the `instagram_content_publish` permission (plus the basic permissions Meta requires — verify in Meta docs), and note the Instagram user id.
6. Host the rendered media at a public https URL — the Graph API downloads files itself; it cannot take local files. For example a folder under the landing site, or Vercel Blob. Layout expected by default: `PUBLIC_BASE_URL/<post id>/media/<file>`. Or fill `public_urls` in `post.json` (same order as `media`).
7. Check the image format: slides are PNG today; Meta's docs have said feed images must be JPEG — verify in Meta docs before the first live run.
8. Check `GRAPH_VERSION` at the top of `publish.mjs` against Meta's current version.
9. Run it:

```bash
export IG_USER_ID=... IG_ACCESS_TOKEN=... PUBLIC_BASE_URL=https://.../ig
node publish.mjs           # dry run — read every URL it prints, open a few in a browser
node publish.mjs --live    # publishes approved posts with planned_date <= today
```

A post is published only when `status` is `approved`, `planned_date` is today or earlier, and `published_id` is null. On success `published_id` and `published_at` are written back to `post.json`, so a second run will not post it again. Never commit the token.

## Later

- **Scheduling:** run `node publish.mjs --live` once a day from cron (or a scheduled CI job) — it only picks up posts whose day has come. Media must already be uploaded by then.
- **AI label:** HTML-rendered graphics and real app screenshots are not AI-generated imagery, so Meta's "AI info" label should not apply. If a post ever uses realistic AI-generated images or video, label it as Meta requires (verify the current rule in Meta docs).

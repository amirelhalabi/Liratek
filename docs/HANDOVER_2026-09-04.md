## 2. How to run the gates

```
yarn test        # scripts/run-tests.mjs — every workspace, never bails, summary table
yarn typecheck   # -ptA, safe
yarn lint        # safe
```

Current baselines, all exit 0:

```
@liratek/core      268 suites   2816 tests
@liratek/backend    46 suites    633 tests
@liratek/frontend  180 suites   1360 tests
desktop e2e        293 tests    (1 known failure — LIRA-175)
web e2e            NEVER RUN
```

**E2E is no longer part of PR CI.** It lives in `.github/workflows/e2e.yml`, `workflow_dispatch`-only,
with a `suite` input (`electron` / `web` / `both`).

Two things about it that are not obvious:

- **"Required" is branch protection, not the workflow file.** Add the check named
  `E2E Tests (Electron)` to `main`'s required checks. It likely will not appear in that picker until
  the workflow has completed one real run.
- A `workflow_dispatch` check attaches to whatever commit was HEAD **at dispatch time**, so pushing
  again after dispatching leaves a required check unsatisfied until re-dispatched. The alternative
  (a `pull_request` trigger gated on a label) was flagged and deliberately not taken.
- **Dispatch `electron` or `both`, never `web` alone** — whether GitHub treats the skipped
  `E2E Tests (Electron)` check as passing or perpetually pending was not verifiable here.

## 4. Traps — all discovered today, all cost time

1. **`node scripts/run-e2e.mjs electron` silently no-ops from a non-interactive shell** — exit 0,
   11-byte log, zero tests. The wrapper exists to catch vacuous runs and reproduced that very
   failure. Use instead:
   `cd frontend && env -u ELECTRON_RUN_AS_NODE npx playwright test --config playwright.electron.config.ts --reporter=list`
2. **`ELECTRON_RUN_AS_NODE=1` is set in agent shells.** If it reaches Electron, every spec dies at
   `waitForEvent("window")` — 108 files failing for an environmental reason that reads as a code bug.
   Always `env -u`.
3. **Piping loses exit status.** `cmd | tail` returns *tail's* status. This masked a real failure
   **four times** today, including a background wrapper reporting success on a run that exited 1.
   Redirect to a file, capture `$?` directly, and record elapsed time — a clean `tsc` prints zero
   bytes and exits 0, shape-identical to a command that never ran.
4. **Git Bash drops `TZ` entirely.** `TZ=X node -e "console.log(process.env.TZ)"` prints `undefined`
   under MSYS. Only `cross-env` passes it. A probe run the other way measures the OS zone and
   produced a wrong conclusion here before being corrected.
5. **Core jest runs SQL and JS in different timezones on Windows** (LIRA-168). Under
   `cross-env TZ=Asia/Beirut`: SQLite `'localtime'` = **+1**, JS `Date` = **+3**. Beirut is +3, so
   the SQL side is two hours off. Both agree at +3 on Linux, so **CI cannot see it**.
6. **`yarn rebuild:native` does work** — contrary to an older note. It rebuilt both copies
   (`node_modules/better-sqlite3` and `node_modules/@liratek/core/node_modules/better-sqlite3`) in
   ~1s. **Probe by constructing a `Database`**, never a bare `require` — the binding loads lazily, so
   `require` succeeds on a mismatched ABI. (Unverified: whether it fails specifically after
   `test:e2e:web`'s rebuild, which is what the older note described.)
7. **Partial `as unknown as jest.Mocked<T>` doubles are invisible to `tsc`.** Three broke today when
   a new method was added. Typechecks stay green; only execution finds them. When you add a method to
   a repository, grep for its doubles.
8. **The e2e harness sets `notificationDurationMs` to 2ms** (`fixtures.ts`) so toasts cannot overlay
   clicks. A spec asserting on toast content **must** opt out with
   `test.use({ notificationDurationMs: null })`. `lira-151` failed for 9 minutes on CI for exactly
   this reason.
9. **Specs written but never run fail on first execution.** Every single one did today. Treat an
   unrun spec as unverified code.
10. **Worktree agents resolve `node_modules` upward to the main checkout**, so gates *are* runnable
    from a worktree — but they share one `better-sqlite3` binary. Never run root `yarn test` from a
    worktree while other work is live; it rebuilds that shared binary.
11. **`selectableUnsettled` excludes LBP non-BILL rows from the Suppliers Settle tab** by deliberate
    design (`Suppliers/index.tsx` ~:841-848, ~:1000-1005, LIRA-119). An LBP OMT SEND cannot be
    settled through the UI today. Not a bug — do not re-file it.
12. **`run-e2e.mjs` passes `--reporter=list,json`**, which overrides the configured reporters, so the
    HTML `playwright-report/` the artifact step uploads was likely never produced. Silent because
    `if-no-files-found: ignore`. Pre-existing, untouched.

## 5. E2E sharding — analysis, for when it comes up again

Proposed: 3 parallel shards + cache the build. **The build is not the bottleneck.**

```
job total   9m10s
playwright  8m30s     <- the actual cost
setup+build   <50s    <- caching this saves ~7%
```

Sharding targets the real 8.5 minutes, but the suite runs **one worker, one accumulating SQLite
database, and a single Electron window reused across every spec file** (rule 15). Partitioning that
splits the shared state. **LIRA-175 is live proof**: `lira-136` passes alone and fails in sequence.

Recommended next step before building anything: run the suite as `--shard=1/3`, `2/3`, `3/3` locally
once and **count** how many specs fail purely from partitioning. If it is a handful, sharding is
worth it. If it is dozens, the real project is making specs self-provisioning first.

Also: for passing a build **between jobs in one run**, use `upload-artifact`/`download-artifact` —
`actions/cache` is for reuse *across* runs. The repo pins `actions/cache/restore@v4`.

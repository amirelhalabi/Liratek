# Money screens audit: POS, Recharge, Debts, OMT/Whish

Date: 2026-10-20. Read-only. No repo files edited, nothing run (no tests, no dev server, no browser).

## How it was run

- `impeccable audit` on POS, Recharge and Debts, `impeccable critique` on OMT/Whish (`features/services/pages/Services`, route `/omt-whish`; there is no `omt-whish` folder), and `break-ui` on Debts in report-only mode.
- Each assessment ran as an isolated read-only sub-agent. Critique Assessment B (the detector) ran separately in the parent context.
- PRODUCT.md and DESIGN.md were absent, so the incumbent code served as design authority.
- Assessment B: `impeccable detect` regex scan.
  - It produced 7 hits. All are false positives: `disabled:text-slate-500` on disabled buttons, which WCAG exempts, and `text-violet-400`, which index.css repaints as the brand accent.
  - It found nothing on Services.
  - Rules that need the rendered page (contrast, tiny text) could not run. Every layout and width claim is inferred from class arithmetic and was not rendered.
- I re-checked these top money risks against source myself: R1, R2, R3, D1, O1, O2, D-cap, and the cancel X in POS checkout. All confirmed.

Paths are relative to `/Users/amir/Desktop/docs/Liratek/frontend/src/features/` unless they start with `packages/`.

Cashier impact:

- **A** = blocks or slows work, or risks a money mistake
- **B** = confusing
- **C** = cosmetic

Size: S < half a day, M about 1–2 days, L multi-day.

## What already works well (do not touch)

- **RTL is clean in all four features.** There are 0 physical `ml/mr/pl/pr/left/right/text-left/right` classes; logical `ms/me/ps/pe/start/end` are used throughout, with `<Ltr>` around amounts.
- **i18n coverage is high.** Nearly all copy goes through `t()`, and no Arabic keys are missing for OMT/Whish.
- **The Debts money core is careful.** Balances are tracked per currency. A stale-response guard prevents one client's data showing on another (index.tsx:336-356). One `computeRepayFigures` feeds both the preview and the submit. The rate used is visible and is the one sent. Forgive is capped. Disabled Confirm buttons explain why.
- **POS guards.** Clear cart, selling a defective unit, and the refund preview all confirm first. Complete Sale is guarded by `isLoading`. The scan field autofocuses after each add.
- **Recharge.** ChargeLineModal has a "This will…" preview, which is a model for every money action. ProviderTabs has `aria-pressed` and focus rings. Card art is lazy-loaded.
- **OMT/Whish.** The partner notices state the real partner and amount. Submit is blocked while the payment is unbalanced. Stale fees are cleared on every tab switch.

## Decisions for the owner (from break-ui)

- **200-target cap:** when everything is ticked, send nothing (pay oldest first). Keep the cap for partial ticks.
- **Debts tables at laptop widths:** stack below about 1440px rather than scroll sideways.
- **Debtor rows:** wrap to 2 lines (name, then phone) rather than truncate.
- **Large manual entries:** a confirmation step above a threshold rather than a hard cap.
- **Zero currency:** show only the currencies that are non-zero.
- **OMT direction convention:** pick the drawer's IN/OUT meaning (as on Transactions) and apply it to the tabs, history and toasts.
